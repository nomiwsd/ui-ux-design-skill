# /ux-critique — Design critique

Read `{{SKILL_PATH}}/references/07-craft-and-accessibility.md`, `references/02-foundations.md`, and `references/04-visual-styles.md`.

Target: $ARGUMENTS

Structure the response in three parts:

1. **What works** — be specific; vague praise is worthless.
2. **What breaks**, ordered by user impact. Check in this order because this is the order that actually determines perceived quality: spacing consistency, type scale and hierarchy, contrast, color discipline (how many colors, is the accent reserved), alignment and grid, radius and border consistency, imagery quality, state coverage, copy, then motion.
3. **Fix list** — concrete values and code, numbered by priority, with an estimate of effort.

Blur test: describe what survives at 8px blur. If everything flattens into one gray mass, hierarchy is the root problem and nothing else matters until it is fixed.

Be direct. A polite critique that leaves the design unchanged has failed.
